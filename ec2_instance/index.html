Cloud Foundations Project

Launch an EC2 server and publish a static site.

This project walks through the full path from creating an AWS account to deploying a simple HTML website on an Ubuntu-based EC2 instance. It is designed to build practical confidence with core AWS infrastructure, SSH access, basic server administration, and static site delivery.

Project Overview

The objective is straightforward: provision a Linux server in AWS, connect to it securely over SSH, install a web server, and publish a simple static website that is reachable through the instance public IP address.

1 AWS account Foundation for launching and managing cloud resources.
1 EC2 instance Ubuntu on a Free Tier oriented compute target.
2 open ports Port 22 for SSH and port 80 for website traffic.
1 public IP The address used to access the deployed website.

Required Deliverables

These are the core tasks expected in the project. Completing them gives you a working static site on AWS and a usable foundation for later infrastructure work.

Implementation Sequence

1
Create or prepare an AWS account

Get familiar with the AWS Management Console and the region defaults available to your account.

2
Launch an Ubuntu EC2 instance

Choose a t2.micro instance type, keep the default VPC and subnet, and ensure a public IP is assigned.

3
Configure inbound access

Allow port 22 for SSH and port 80 for HTTP in the instance security group.

4
Create or reuse an SSH key pair

Use the private key from that pair to authenticate your connection to the Linux server.

5
Connect and prepare the server

SSH into the machine, update the package index, and install a web server such as Nginx.

6
Deploy a simple HTML page

Place a static HTML file in the web root and confirm it is accessible through the instance public IP address.

Checklist

  • Ubuntu Server AMI selected for the EC2 host.
  • t2.micro chosen to stay aligned with AWS Free Tier guidance.
  • Default VPC and subnet used for a minimal first deployment.
  • Inbound rules created for SSH and HTTP traffic.
  • Public IP address assigned and verified for browser access.
  • Nginx installed and serving the deployed HTML content.

Deployment Flow

The project is small by design, but it covers the essential cloud workflow: provisioning, access control, operating system setup, web server installation, and publishing content to a public endpoint.

ssh -i my-key.pem ubuntu@your-ec2-public-ip sudo apt update sudo apt install -y nginx sudo cp index.html /var/www/html/index.html

What this teaches

  • How AWS resources are created and exposed to the internet in a controlled way.
  • How to connect to Linux servers over SSH using a key pair instead of a password workflow.
  • How a web server like Nginx delivers static files from a Linux host.
  • How security groups, instance sizing, public networking, and deployment steps fit together.

Stretch Goals

Once the base deployment works, the next improvements are about domain management, encryption, and automation.

Custom Domain

Use Amazon Route 53 to map a friendly domain name to the EC2-hosted website.

HTTPS

Issue a free TLS certificate with Let's Encrypt and serve the site securely over HTTPS.

CI/CD Pipeline

Automate deployments with AWS CodePipeline so site changes can be published with less manual effort.

Learning Outcomes

After finishing this project, you should be comfortable launching EC2 instances, opening the right network access, connecting through SSH, and deploying basic web content on cloud infrastructure.

AWS Resource Basics

Understand what an instance is, how instance types differ, and what a first cloud deployment requires.

Linux Server Administration

Gain hands-on familiarity with package updates, service installation, and moving files into a web root.

Cloud Website Delivery

Deploy and verify a static website through the public IP of the running EC2 instance.
